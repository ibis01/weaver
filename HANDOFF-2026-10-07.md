## What Shipped This Session — Smart Money Radar

A complete feature arc, ten commits, from contract to end-to-end.

**The brief was**: find wallets that have historically been early,
detect when independent ones begin accumulating the same meme asset,
and identify that convergence *before* broad market momentum confirms
it. Never a single-wallet signal. Never call it "pump detected."
Backtest before production. No look-ahead.

**What we built**, in dependency order:

1. `js/intelligence/types.js` — added `SMART_MONEY_ENTRY` to the
   canonical signal enum, `FRESHNESS_WINDOWS.SMART_MONEY_ENTRY = 1800`,
   `SOURCE_RELIABILITY.smart_money_radar = 0.6`, bumped
   `CONTRACT_VERSION` to `intelligence-contracts-v2`.

2. `js/intelligence/smart-money/wallet-history.js` — direct Blockscout
   fetch of per-wallet per-token transfer history, 24h client cache,
   canonical oldest-first trade list. Never throws.

3. `js/intelligence/smart-money/wallet-profiler.js` — per-wallet
   aggregate: realized PnL, winning-trade rate, day-ahead early-entry
   rate. Reuses `W.smart.analyzeWallet` + `W.smart.buildPriceMap`.
   `asOf` is a hard truncation boundary at both trade filter and
   window. Never silently defaults.

4. `js/intelligence/smart-money/convergence-detector.js` — detects N
   independent historically-early wallets accumulating the same token
   within a short window. `N_MIN = 3`, `INDEPENDENCE_MIN = 0.7`,
   `DEFAULT_WINDOW_MS = 15 min`. Independence = `1 - min(coTiming,
   amountProx)` — two wallets look like the same actor only if
   similar on BOTH axes.

5. `js/intelligence/smart-money/momentum-detector.js` — three-state
   classification: `PRE_MOMENTUM` / `MOMENTUM_EMERGING` /
   `MOMENTUM_CONFIRMED` / `unknown`. Trailing-only windows. Cadence
   guard refuses when median gap between candles is outside
   `[30min, 2h]`. v3 exposes `classifyFromCandles` test hook so the
   guard is testable without monkey-patching the frozen `W.api`.

6. `js/intelligence/smart-money/smart-entry-engine.js` — composes
   convergence + momentum + wallet quality into a canonical
   `SMART_MONEY_ENTRY` signal via `W.intelligence.create.signal`.
   Refuses to emit on `MOMENTUM_CONFIRMED` (the promise is "before
   confirmation") and on `unknown` momentum. 8-factor score from the
   brief; three factors left null where the data is not available,
   weights renormalize over the non-null subset.

7. `js/features/smart-radar.js` — manual scan card on `#/smart`.
   One button, one token, one pipeline run. Bounded at 8 wallets.

8. `js/features/smart-radar-auto.js` — user-controlled watchlist and
   a scheduler that scans exactly one token per 10-minute cycle, only
   while the tab is visible. Auto-scan off by default. Signal cache
   holds the last 100 results for 24h.

9. `js/intelligence/events.js` — `collectSmartMoneyEvents()` reads
   the auto-scan cache and returns canonical signals. Added to the
   `collectEvents` batch. `CACHE_VERSION` bumped from 6 to 7.

10. `js/intelligence/decision-engine.js` — `DISCOVERY_TYPES =
    {SMART_MONEY_ENTRY}` with `0.15` relevance baseline. Without this,
    the score>0 filter in `run()` dropped every radar signal, because
    the user has no prior connection to a discovery-shaped token.

11. `sw.js` — v4 never serves a stale entry point from cache.
    `index.html`, `dist/bundle.js`, `dist/bundle.min.js` use
    `cache: "reload"` with an 8s timeout; everything else stays
    cache-first with background revalidation. This eliminated the
    recurring SW cache-stale tax that cost this session ~20 minutes
    per step.

**What is NOT done from the brief**:

## Session 2 — Critical Lessons

These are process lessons from ten patch attempts and three
"the file is not what I assumed" moments. They are the most
expensive thing we learned.

**1. Diagnose before writing a patch.**
Before touching a file, run:
```sh
grep -n "function \|const [A-Z_]* =" <target>
sed -n '<range>p' <target>
Read the actual shape. Do not design against the shape you
remember from an earlier paste. Two files in this session
(events.js and decision-engine.js) turned out to have a
different _internal shape, a different function name
(_dedupe vs deduplicateSignals), and a different cache
versioning scheme than I had assumed.

2. Use regex and byte-level find, not exact substring.
CRLF line endings, Unicode box-drawing characters inside
comment blocks, and non-breaking spaces all break b"..."
anchors. types.js has non-ASCII in its header comments;
events.js has box-drawing; the sw.js header has full-width
dashes. Always match against bytes.find() and print
context on failure.

3. Every patch prints its own change.
Each patch script must (a) locate every anchor and print
FOUND/NOT FOUND, (b) abort before writing if any anchor is
missing, (c) print a one-line summary of what it changed. If
the paste does not show these, the patch did not run — do not
assume it did.

4. Object.freeze on a namespace blocks sibling attach.
W.smartRadar was originally Object.freeze({...}), which
silently dropped W.smartRadar.auto = ... in sloppy mode. Only
_internal should be frozen. Top-level namespaces are
extensible by convention (matches W.smartMoney, W.intelligence).

5. W.api is frozen. W.api.ohlcv = newFn silently fails.
Test hooks belong on _internal of the consuming module, not as
monkey-patches on frozen globals.

6. The service worker was the hidden tax. Before sw.js v4,
every code change required DevTools → Application → Unregister SW,
Storage → Clear site data, then Ctrl+Shift+R, before the browser
would fetch the new bundle. If the new SW is not yet deployed for
some future session, this is how to bypass it:
js

await navigator.serviceWorker.getRegistrations()
  .then(rs => Promise.all(rs.map(r => r.unregister())));
await caches.keys().then(ks => Promise.all(ks.map(k => caches.delete(k))));
location.reload();

Anti-Patterns From This Session

    Designing a patch against a remembered file shape. The
    file has changed. Read it first.

    Trusting a grep -c on the minified bundle. String
    constants survive minification but so does almost everything
    else, and a false positive means the change never landed.
    Grep the unminified dist/bundle.js too.

    Assuming a patch ran because you wrote it. Every patch
    must print what it did. If the paste does not show the
    printed output, the patch did not run.

    Freezing a namespace you intend to extend. See Lesson 4
    above.

    Adding tests without a test hook. momentum-detector.js
    v2 could not be tested against synthetic candles because
    W.api is frozen. The fix is a _internal.classifyFromCandles
    that exercises the same code path as detect(). Any module
    that has non-pure logic and calls a frozen external should
    expose an _internal helper that takes the external's output
    as a parameter.

    Letting a working tree go dirty across a session. The
    context.js change that has been sitting uncommitted since
    Session 1 has cost us nothing yet, but it will the first time
    someone runs git add -A.
